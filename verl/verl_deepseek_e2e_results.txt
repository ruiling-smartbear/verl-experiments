== Notes
- Same three checkouts with the default AutoTokenizer (transformers 5.16.1 picks LlamaTokenizerFast for this checkpoint):
  decode drops every space and the ｜/▁ characters of the DeepSeek markers ('<toolcallsbegin>...', 'Whatarethecurrent...'),
  so verl's exact-marker parser saw no call while a tolerant regex did. Loading the same files as Qwen2TokenizerFast decodes
  correctly and the parser works. This is a tokenizer-class issue of that checkpoint under transformers 5, not a verl one.
- With thinking on (no --nothink) the model spent the whole 900-token budget reasoning on turn 1; with a 2500 budget it
  produced the call after ~1900 tokens. --nothink prefills an empty think block so the calls come immediately.
- An earlier run with deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B: its template renders tool_calls only when content is None,
  so the pre-#7630 append does not raise there (same as DeepSeek-V3), and the 1.5B model neither calls the tool nor uses the
  result. Kept as a plumbing check only.
- DeepSeek-R1-0528-Qwen3-8B's template re-opens <｜tool▁outputs▁begin｜> for every tool turn (no conversation-global
  is_output_first), so the outputs-prefix fix is neutral here ("matches template" on both turns, before and after).
- GPU time for the whole rollout-level session: about 55 min of H100 (roughly $3.6), most of it environment setup.
